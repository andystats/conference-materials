ACIC 2026 teaching demo

Run vanilla SHAP, then tell SHAP what the DAG already knows.

This companion page supports a live causal SHAP demo. The simulated data include upstream causes, mediators, and downstream proxy measurements that are predictive but not causal drivers of the outcome.

Demo Flow

The point is not to make SHAP causal by assertion. The point is to show what changes when the attribution procedure is given a correct causal ordering for the data-generating process.

Step 1 Run vanilla SHAP The prediction model sees the proxy variables and rewards them because they summarize downstream clinical state.
Step 2 Reveal the true DAG The demonstrator supplies the known simcausal DAG, including the fact that proxy nodes are descendants, not causes.
Step 3 Run causal SHAP DAG-constrained permutations move attribution upstream toward causes and mediating pathways with total effects.

Reference Run

The checked-in reference run uses 2,500 simulated rows, 18 predictors, a gradient boosting outcome model, and a laptop-friendly causal SHAP Monte Carlo setting.

0.941 held-out model R2
51% -> 12% downstream proxy attribution share
0.22 -> 0.44 Kendall rank agreement with true total effects
4.33 -> 3.33 mean absolute rank error

Run The Local App

The GitHub Pages site is static. The live workflow runs locally as a Python Shiny app and uses the same simcausal output files shown above.

cd acic-2026-causal-shap\app py -3.13 -m pip install -r requirements.txt py -3.13 -m shiny run --port 8000 app.py

Open http://127.0.0.1:8000. In the app, run Standard SHAP only first, then switch to Compare standard vs causal SHAP with the Known true DAG selected.
